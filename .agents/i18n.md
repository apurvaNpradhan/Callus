# i18n Guidelines

## Copy Keys

Use the `{FEATURE_OR_PAGE}__{...MORE_SPECIFIC_IDENTIFIERS}` convention.

Examples:

- `home_page__hero_title`
- `auth__sign_in_title`
- `navbar__dashboard`

## English-Only Default

Add new copy keys to `packages/i18n/messages/en.json` only by default. Do not edit `de.json` or any other non-English locale unless the user explicitly asks for translation work.

Translation is a separate agent workflow. Do not run machine translation or manually fill translated locale files as part of ordinary feature work.

## Paraglide Codegen

If new or renamed keys need generated Paraglide modules for typecheck or runtime, run:

```sh
vp run --filter @callus/i18n build
```

This is codegen, not translation.

The root `dev`, `check`, and `fix` scripts already run the conditional `i18n:ensure` preflight. It checks for Paraglide's required generated entrypoints and compiles only when any are missing. Do not remove the `dev` preflight: package development scripts run in parallel, so the web app can otherwise import the generated runtime before the i18n watcher completes its first compile on a fresh clone.

## Locale ownership

- Signed-in users use the validated `user.locale` Better Auth field as the account-wide preference. Existing accounts without a value resolve to English.
- Guests use a temporary locale choice. On web, resolve the validated locale cookie before `Accept-Language`; on native, resolve AsyncStorage before Expo device locales. Both fall back to English.
- At sign-in, the account preference wins over a guest's temporary choice. At sign-up, pass the current guest locale when creating the account.
- Web URLs are unprefixed. Resolve locale per request in `apps/web/src/server.ts`, then mirror the resolved guest locale to the cookie for the next request. Do not add locale route params or localized alternate URLs.
- Native uses `@callus/i18n/native/messages` and `@callus/i18n/native/runtime`, compiled from the same Inlang message sources with the native-safe global-variable strategy. Keep this generated target separate from the web runtime.
- Language changes for signed-in users go through Better Auth `updateUser`; guest changes update only the temporary client cookie/storage. Update the reactive Paraglide/React state after persistence succeeds.

## Gotchas

- Do not call `m.*()` at module scope for labels, navigation config, or other long-lived objects. Resolve messages during render or request handling so SSR and hydration use the resolved locale.
- Keep the native locale provider reactive. Paraglide `setLocale(..., { reload: false })` does not notify React by itself.
- When changing supported locales, update the auth `additionalFields.locale` enum and account schema, regenerate Better Auth's Drizzle schema, compile both Paraglide targets, and add native/browser locale resolution tests.
